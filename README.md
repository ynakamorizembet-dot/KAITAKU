# カイタク(KAITAKU) — AI営業自動化SaaS

中小企業・個人事業主が自分で営業・集客(リード発掘〜アウトリーチ〜返信管理〜契約管理)を回せるようにする、複数チャネル対応の営業・マーケティング自動化SaaS。プロダクト名は「カイタク(KAITAKU)」(2026-08-16確定、「新規開拓」の"開拓"から)。前身は`aiman-one`(個人利用・Outlook限定)。詳細な方針・ガードレールは`CLAUDE.md`を参照。

**重要:** 「Googleマップでホームページなし企業を探してAI営業メールを送る」は、数あるチャネルの1つ(法人向けテンプレート)であり、プロダクトの全体像ではない(2026-08-15夜、ボス指摘により明確化)。法人向けメール・個人向けSMS配信を並列チャネルとして持つ汎用エンジンとして設計する。

## 機能スコープ

### MVP(フェーズ1・今回着手)
- ユーザー登録・ログイン(マルチテナント)
- 企業自動収集(ユーザー自身のGoogle Places APIキーを登録して使用)/ 法人向けチャネル
- AI営業メール文面生成(ユーザー自身のAI APIキーを登録して使用)。AI生成後の手動編集にも対応
- メール送信:Gmail・OutlookをOAuth連携し、ユーザー自身のアカウントから送信(下書き確認→送信の2段階)
- SMS配信:個人向けキャンペーン・お知らせの一斉配信チャネル(同意済み連絡先のみ)
- 企業リスト・ステータス管理(未送信/送信済み/返信あり/興味あり等)
- 契約管理(admin):運営(ボス)が全顧客のプラン種別・トライアル終了日・契約更新日を横断確認できる画面
- 見やすいダッシュボードUI(グラスモーフィズム、ライトテーマ)

### フェーズ2(次段階)
- Stripe等での課金(**年間契約¥60,000〔月換算¥5,000〕を基本プラン、月払いは¥6,000/月**。2026-08-15、競合調査を踏まえて確定)
- SMS送信の実接続:月10通無料、以降1通¥20
- SMS送信業者の選定(`04_Research_Intelligence`が比較中。国内サービス1通6〜10円 vs Twilio約13円)
- 返信の自動検知・ステータス自動更新の精度向上
- 契約終了間近の顧客への自動アラート(`03_Operation_Auto`と連携し仕組み化を検討)

## 前身(aiman-one)からの変更点

| 項目 | aiman-one(旧) | 今回(新) |
|---|---|---|
| メール送信 | Outlookのみ | Gmail・OutlookをOAuth連携(拡張可能) |
| API費用 | 運営側負担想定 | ユーザー自身のAPIキー(BYOK)で運営コストほぼゼロ |
| SMS | なし | 同意ベースのみ、追加課金あり |
| 利用形態 | 個人利用(単一ログイン) | マルチテナントSaaS(販売前提) |
| デザイン | シンプルな管理画面 | shadcn/ui系のモダンなデザイン |

## ディレクトリ構成

- `app/(dashboard)/` … ログイン後の画面(ダッシュボード・企業リスト・メール送信・SMS配信・返信管理・契約管理)。すべて`app/(dashboard)/layout.tsx`でログイン必須(未ログインは自動で`/login`へ)
- `app/login/` … マジックリンク(パスワード不要)によるログイン画面
- `app/auth/` … 認証コールバック・ログアウト処理
- `lib/supabase/` … Supabaseクライアント(`client.ts`=ブラウザ用、`server.ts`=サーバー用、`admin.ts`=service_role専用・サーバーからしか読み込んではいけない)
- `middleware.ts` … 未ログイン時のリダイレクト、セッションの自動更新
- `supabase/schema.sql` … データベーススキーマ。SupabaseダッシュボードのSQL Editorに貼り付けて実行する
- `components/` … UIコンポーネント
- `.env.example` … 必要な環境変数の一覧(実キーは`.env.local`、Git管理外)

## セットアップ手順(ボス作業)

1. [supabase.com](https://supabase.com) で無料アカウントを作成し、新規プロジェクトを作成(**アカウント作成はE.V.A.では代行できないため、ボス本人での操作をお願いします**)
2. プロジェクトの「Project Settings → API」から、Project URL・anon public key・service_role keyの3つをコピー
3. `.env.example`を`.env.local`にコピーし、2でコピーした値を`NEXT_PUBLIC_SUPABASE_URL`・`NEXT_PUBLIC_SUPABASE_ANON_KEY`・`SUPABASE_SERVICE_ROLE_KEY`にそれぞれ貼り付け
4. Supabaseダッシュボードの「SQL Editor」で`supabase/schema.sql`の中身を貼り付けて実行(テーブル・RLSポリシーが一括で作成されます)
5. Supabaseダッシュボードの「Authentication → Providers」で、Emailプロバイダーが有効になっていることを確認(初期状態で有効なはずです)
6. ターミナルで `npm install` → `npm run dev` → `http://localhost:3000` を開くと、自動的に`/login`へ案内されます。ご自身のメールアドレスを入力すると、そのアドレス宛にログインリンクが届きます(パスワード不要)
